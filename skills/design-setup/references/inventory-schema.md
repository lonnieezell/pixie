# Design inventory schema

The shape of `docs/agents/design-system.md`. Every stack uses the same sections in the same order, so a design skill can read any repo's inventory cold. Leave a section in place even when it's empty, and write `None found.` under it. The exceptions: `## Setup offers` keeps its table header, and the protected sections hold only what a human wrote or answered, so they can be empty.

Rules for the file:

- Sections are `##` headings with exactly the names below. Headings inside a section are `###` or deeper, so each `##` heading marks the end of the section before it.
- Every generated entry names its source: a file path, with a line number where it helps. The freshness check maps changed files back to entries through these paths.
- `## Annotations` and `## Rubric overrides` are **protected**. They belong to humans and stay last in the file. The skill copies them byte for byte and never rewrites them.
- `## Setup offers` is written by the skill, but only appended to. A refresh never clears it.

## Field notes

**Header.** `Source commit` is the full SHA of `HEAD` when the scan ran. `Scanned paths` lists every folder and file the scan read, repo-relative, in backticks. The freshness check diffs exactly these paths.

**Stack.** List anything detected but not supported (React Native, Vue, Livewire) under "Detected but not supported". It's still catalogued, but later design skills can't preview or capture it.

**Baseline target.** One of `Widely available`, `Newly available`, `Baseline YEAR`, or a browserslist query copied as is. Always name the source: `browserslist`, `CLAUDE.md`, `AGENTS.md`, `asked`, or `default`.

**Tokens.** Group by role: colours, spacing, type scale, radii. Add shadows, breakpoints or motion only when the repo defines its own. A framework default the repo doesn't override is a single line ("Tailwind default scale"), not a copied table. Name colours by role (primary, surface, text, muted, border, danger, success, warning) where the repo makes the role clear. Tokens the skill bootstrapped say `bootstrapped` in the Source column.

**Components.** One row per component. "Path / import" is the import a new file would write (React), the tag or directive (Blade `<x-alert>`, `@include('partials.alert')`), or the call (CI4 `view_cell('App\Cells\AlertCell::show')`, `$this->include('partials/alert')`), plus the file path. "When to use" says what it's for in one line. Status is `preferred` or `legacy`, followed by where it came from: `(annotation)`, or `(inferred: REASON)`. Precedence:
1. A `status:` line for the component in `## Annotations` decides it, always.
2. Otherwise it's inferred, and the reason is written.
3. A component with no rival is `preferred`.

A refresh re-infers a changed component's status only when it has no annotation.

**Patterns.** Repeated markup that isn't already a component. "Canonical example" is the cleanest single occurrence, as `path:line`. "Occurrences" counts the occurrences and the files they're in. The suggestion is only a suggestion. Nothing gets refactored.

**Preview surface.** `storybook (PATH)`, `harness (/__preview)`, or `temporary`.

**Launch fallback.** The launch command and URL the user confirmed (for example `php spark serve` at `http://localhost:8080`), for when there's no verifier. `none` when the repo has a verifier: design skills look for `.claude/skills/verify-*/` themselves when they run.

**Rules.** House conventions a new screen must follow, each with its evidence. Don't invent rules the code doesn't show.

**Setup offers.** One row per offer, with the answer and the date. Row names and when each is written are in the skill's step 7. `/design-critique` adds a **Gitignore critique screenshots** row the first time it asks. An offer with a row is never asked again.

**Annotations.** Free-form notes for design skills. A line in the form ``- status: `Name` = preferred`` or ``- status: `Name` = legacy`` sets that component's status (see Components).

**Rubric overrides.** Changes to the design critique rubric for this repo. A line in the form ``- drop: `RUBRIC-ID` `` (any reason after it) removes that rubric item, and `/design-critique` suppresses any finding that cites it. Any other line is a house rule the critic follows, and it wins over the core rubric.
